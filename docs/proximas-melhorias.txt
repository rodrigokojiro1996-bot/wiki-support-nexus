1.3 ROTA DA API
-------------------------------------------------------------
  POST /api/manuais/importar?modulo=pdv
    corpo: os bytes do arquivo (mesmo estilo do POST /api/imagens, sem precisar
           do pacote python-multipart)
    cabecalho: X-Arquivo: <nome do arquivo, URL-encoded>
    resposta 200: o rascunho {titulo, subtitulo, secoes, fontes, tabelas, avisos}
    NAO salva o manual. Quem salva e o POST /api/manuais de sempre.

- Titulo sugerido: o primeiro titulo do documento; senao, o nome do arquivo
  sem extensao.
- fontes: [nome do arquivo]. Acrescentar "fontes" (opcional) ao ManualEntrada
  para o POST /api/manuais gravar a origem do manual.
- Rota "def" (nao "async def"): o FastAPI roda em thread e a conversao de PDF
  nao trava o servidor.
- Metricas: contador nexus_importacoes_total{formato, resultado} e histograma
  de duracao, no mesmo padrao das metricas do PDF.


1.4 SEGURANCA DA IMPORTACAO
-------------------------------------------------------------
- Tamanho maximo do arquivo (sugestao: 20 MB) -> 413.
- Tipo pelos BYTES, nao pela extensao (mesma ideia de extensao_imagem):
    %PDF-         -> pdf
    PK\x03\x04    -> docx (e conferir que existe word/document.xml no zip)
    texto puro    -> txt (decodifica em UTF-8, UTF-8 com BOM ou cp1252)
  Qualquer outra coisa -> 415 com mensagem clara.
- Recusar com mensagem explicativa:
    .doc (Word antigo)   -> "salve como .docx e importe de novo"
    .docm (com macros)   -> "salve como .docx sem macros"
- Zip bomb: antes de abrir o docx, somar file_size de zipfile.ZipFile.infolist()
  e recusar acima de um limite (ex.: 100 MB descompactado) ou com taxa de
  compressao absurda.
- PDF: limite de paginas (ex.: 200) e de imagens extraidas (ex.: 300).
- Continua valendo: senhas mascaradas (servicos/limpeza.py), autores removidos,
  nenhuma macro ou script executado, nada escrito fora de dados/.
- Dependencias: pypdf, python-docx e pillow passam de
  requirements-ferramentas.txt para requirements.txt (a API passa a usar) e
  entram na imagem Docker. Versoes continuam travadas com ==.

2.1 CI NO GITHUB ACTIONS              (fazer primeiro - protege o resto)
-------------------------------------------------------------
Hoje nao existe .github/. Os testes existem, mas so rodam quando alguem lembra.

.github/workflows/ci.yml, em todo pull request e push na main:
  job backend:
    - actions/setup-python (mesma versao do Dockerfile)
    - pip install -r backend/requirements-dev.txt
    - python -m pytest -q
  job frontend:
    - actions/setup-node (versao do Dockerfile)
    - cd frontend && npm ci && npm run build   (o tsc -b confere os tipos)
  job prometheus:
    - promtool check config docker/prometheus/prometheus.yml
    - promtool test rules docker/prometheus/alertas.test.yml
  job docker:
    - docker build . (sem push) - garante que a imagem continua montando

Boas praticas no proprio workflow:
- Actions travadas por SHA de commit (nao so @v4), com o numero da versao em
  comentario.
- permissions: contents: read no topo do arquivo.
- Cache de pip e npm (actions/setup-python e setup-node ja fazem com
  cache: pip / cache: npm).
- concurrency por branch, cancelando execucao antiga do mesmo PR.

Como conferir: abrir um PR de teste com um teste quebrado de proposito e ver
o CI ficar vermelho.
